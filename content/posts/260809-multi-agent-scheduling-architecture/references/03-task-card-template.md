# 任务卡模板

主脑拆任务时，每个任务用一张标准化的"任务卡"描述。
这个模板确保每个执行器拿到的任务都有明确的边界和验收标准。

## 模板

```markdown
# 任务卡：<一句话任务标题>

## 目标
<!-- 这个任务要达成的具体结果是什么，一到两句话说清楚 -->

## 非目标
<!-- 明确哪些事情不在这次任务范围内，防止执行器越界 -->

## 修改边界
- **允许**：<!-- 允许修改的文件清单或目录范围，越具体越好 -->
- **禁止**：<!-- 绝对不能碰的文件/目录，及原因 -->

## 完成条件
- [ ] <!-- 验收条件 1：具体的、可验证的 -->
- [ ] <!-- 验收条件 2 -->
- [ ] 所有测试通过：`<具体的测试命令>`
- [ ] 代码提交信息包含任务追踪标识

## 基线信息
- **起点 commit**：<!-- 出问题时的回滚点；必须先 fetch 远端后填写 -->
- **分支**：<!-- 在哪个分支上干活 -->
- **Worktree**：<!-- 是否使用独立副本隔离；路径是什么 -->
- **唯一写入者**：<!-- 同一时刻只有一个工具/会话可以写这份代码 -->
- **执行器与模型**：<!-- 派给谁、用什么模型、什么推理档位 -->
- **任务类型**：<!-- frontend-ui / backend-logic / refactor-migration / tests-docs / glue-scaffold / review / debug -->
- **复杂度**：<!-- S（百行内）/ M（数百行）/ L（千行级） -->

## 当前状态
- **阶段**：<!-- 待派发 / 执行中 / 待验收 / 已完成 / 已废弃 -->
- **最近更新**：<!-- 时间 + 一句话进展 -->
```

## 设计要点

1. **修改边界是核心**：执行器只能改"允许"列表里的东西，碰了"禁止"的直接判定违规。这是防止 Agent 越界最有效的手段。

2. **完成条件必须可验证**：不能写"代码质量好"这种主观描述，要写"运行 `npm test` 全部通过"这种可执行的命令。

3. **唯一写入者原则**：同一时刻、同一份代码只允许一个工具/会话写入。这是防止多个 Agent 互相覆盖的关键规则。

4. **任务类型是路由依据**：调度器根据这个字段决定派给哪个执行器。类型词表固定不变——变了就没法做历史对比分析。

5. **起点 commit 是安全网**：出了问题可以回滚到这个点。注意要用远端的最新版本，不要用本地可能落后的版本。
